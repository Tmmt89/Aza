## 1. Проект

Aza («голос» по-чеченски) — нативное macOS-приложение вокруг выреза MacBook:
время намаза, локальная диктовка, автокоррекция раскладки (ru/en/ce),
история буфера обмена. Некоммерческое, MIT, распространение через
подписанный DMG с сайта (НЕ App Store). Полная спецификация: `docs/SPEC.md`.

Фундаментальные принципы (не нарушать):
- всё локально: никакой телеметрии, аккаунтов, облачной синхронизации;
- никогда не трогать secure-поля, менеджеры паролей, терминалы, URL/email;
- ложное исправление хуже пропуска (асимметрия цены ошибки);
- сторонние зависимости — только после проверки лицензии (см. §6).

## 3. Приложение и его статус

**`Aza/` (Xcode)** — рабочее приложение:
   хоткей ⌘⇧A (тестовая вставка), монитор слов, трёхстадийная коррекция
   ru/en/ce с защитой чеченских слов, отмена, исключения, история буфера MVP.
   Коррекция работает ВО ВСЕХ приложениях, кроме deny-list (ExcludedApps:
   терминалы, IDE/редакторы кода, менеджеры паролей — спецификация §6);
   secure-поля отсекаются на уровне элемента; ролевой фильтр isTextInput
   для коррекции снят (Notes/браузеры/Electron отдают нестандартные роли),
   «текстовость» функционально гарантирует replaceTypedText. Путь вставки
   из истории буфера пока ролевой фильтр сохраняет — тот же Notes-класс
   приложений может отклонять вставку (техдолг).

## 4. Чеченский модуль — реализован полностью

### Конвейер словаря (`Tools/BuildChechenLexicon`, SwiftPM)
Команды: `build`, `coverage` (go/no-go ≥70%), `selftest` (диагностика).
Источники с закреплёнными ревизиями; канонизация палочки; фильтр русских
заимствований; взвешивание источников (`maxShare`) и буст лемм (`boost`).

**Итоговый словарь:** 63 601 слово / 1,4 МБ; held-out покрытие 98,1%
(4-й источник NM-development/nmd-ce-ru-171k-v0, MIT, maxShare 0.2;
FP-веттинг: порог соседа по первой клавише поднят 10→50 — воздержаний
на топ-2000 русских слов стало меньше бейзлайна, 66 против 79; защита
«хало» сохранена, частота 103; бренды чисты; рецепт персонального
разговорного корпуса — Aza/Resources/README.md).
Русский фильтр — 3009 слов (только ru-частота ≥500: хвост pyspellchecker
содержит мусор «ху»/«ду»/«вай», вычёркивавший чеченскую лексику), плюс
спасение омографов порогом чеченской частоты (`russianKeepMinCount: 100`
в config.json — возвращает «со»/«ду»/«вай», но не «мало» 31/«было» 0).
Известная дыра данных: разговорные формы («ху» вместо «хӏун») в
литературном корпусе отсутствуют — нужен разговорный источник; хардкод
слов запрещён владельцем. Артефакт: `Aza/Resources/chechen-lexicon.tsv`
+ manifest.json.

### Движок коррекции: фиксированный порядок в `directCorrection`
1. **Нормализация палочки** — гипотезы подмен; принимается единственный
   вариант, существующий в словаре; без словаря — legacy-жадная замена.
2. **en→ru ремап** → если результат валидно-русский:
   `firstKeyAlternativeIsChechen` — замена/пропуск ПЕРВОЙ клавиши даёт
   частотное (≥10) чеченское слово → НЕОДНОЗНАЧНО, не исправлять.
3. **Опечаточная стадия** (настройка OFF по умолчанию): кириллица, длина ≥4,
   нет в чеченском словаре, не русское слово, ровно один сосед на расстоянии 1
   с сохранением первой буквы, кандидат не имя собственное.
4. **guard looksChechen** — маркеры (ӏ хь къ кх аь оь уь юь яь) или слово
   в словаре → латинизировать нельзя.
5. **ru→en ремап** + abstention `hasOneEditMatch(of:)` true → nil.

### Контекст фразы (25.08 вечер)
Буфер последних 4 слов в GlobalHotKey. Форвард: после чеченского слова
2-буквенное слово с частотным чеченским ремапом (порог 50; для 3+ — 20;
пороги масштабируются с корпусом, см. комментарий в chechenContextRemap)
исправляется. Бэквард: исправление в чеченское слово ретроактивно
расширяет ту же атомарную AX-замену на непрерывный хвост предыдущих
неисправленных слов с частотным ремапом («[e le wbuf[m» → «[e ду цигахь»);
слово без такого ремапа (бренд/англ/рус, ВЕРХНИЙ регистр внутри,
валидное английское) обрывает расширение. Undo двойным Shift откатывает
всю фразу, слова уходят в исключения пословно. Фонотактика (чередование
согласных/гласных как сигнал чеченского для OOV-слов) — идея Этапа 5,
не реализована.

### Отмена и пользовательские списки
- Двойной правый Shift (<0,7 c): откат последнего исправления тем же
  AX-механизмом замены (текст перед кареткой обязан совпасть) + исходное
  слово в never-correct. Хранится одна последняя правка.
- Списки: `~/Library/Application Support/Aza/user-words.json`,
  форма хранения — нижний регистр + каноническая палочка.

| `і` | U+0456 | появляется при lowercasing U+0406 |

## 8. Грабли (уже наступали — не повторять)

1. **Инкрементальная сборка SwiftPM иногда отдаёт старый бинарник** после
   правок ядра. Признак: тесты зелёные, а поведение CLI прежнее.
   Лечение: `rm -rf .build` и пересборка.
2. **`.gitignore` и регистронезависимая ФС macOS**: шаблон `sources/`
   зацепил папку `Sources/` с кодом конвейера — коммит вышел без исходников.
   Папки датасетов называть иначе (сейчас `datasets/`).
3. **Многострочный python через `python3 -c "…"` искажается интеграцией
   терминала** — писать во временный файл-скрипт и запускать его.
4. **git без `--no-pager` зависает** в пейджере.
5. Путь проекта содержит пробел — всегда в кавычках.
6. `@Published` / `ObservableObject` требуют явного `import Combine`.
7. `Scene` не имеет `.onAppear` — старт мониторов в init или View.
8. У палочки 4 кодовых точки (см. §6) — проверять литералы глазами нельзя,
   только аудитом.
9. **Сборка без подписи ломает TCC и Keychain.** Локальная пересборка с
   `CODE_SIGNING_ALLOWED=NO` делает бинарник «другим приложением»: слетают
   Input Monitoring/Accessibility (коррекция молча не работает), а чтение
   ключа истории вызывает модальный диалог Keychain прямо в `AzaApp.init`
   (приложение висит без иконки в меню). Собирать только со штатной
   подпиской «Aza Development»; вариант без подписи — исключительно CI.
10. **Процессы, запущенные из shell-обёртки Claude, наследуют её TCC.**
   `nohup "$BIN"` показывает права терминала, не Aza — для честной проверки
   запускать через `open`, диагностика старта пишется в stderr
   (`open --stderr файл`).
11. **Второй хоткей Carbon молчит, если первый возвращает `noErr`.**
   `InstallEventHandler` ставит обработчики в ЦЕПОЧКУ: `noErr` означает
   «событие обработано», и до следующего обработчика оно не доходит.
   Чужой `EventHotKeyID` обязан получить `eventNotHandledErr` — иначе
   ⌘⇧A съедает событие ⌃⇧D (диктовка «не работает» при успешной
   регистрации). Симптом: `register()` вернул nil, а колбэк молчит.
12. **У agent-приложения (LSUIElement) не всплывает TCC-диалог микрофона.**
   `AVCaptureDevice.requestAccess` в неактивном процессе не показывает
   запрос. Лечение: `NSApp.activate(ignoringOtherApps:)` и — надёжнее —
   реальное обращение к устройству (запуск AVAudioEngine), которое и
   поднимает системный запрос.
13. **WhisperKit качает модели в `~/Documents/huggingface`.** Документы
   пользователя засорять нельзя: `downloadBase` — это КОРЕНЬ кэша
   (внутри него создаётся `models/argmaxinc/…`), а токенизатор качается
   отдельно и требует ещё и `tokenizerFolder`. Оба указывают на
   Application Support/Aza/huggingface.
14. **Настройки в AzaApp.init читаются ненадёжно.** Выбранный город
   терялся при каждом запуске, пока чтение не перенесли на первый виток
   главного цикла (`DispatchQueue.main.async`). Настройки с безопасным
   значением по умолчанию этого не замечают — у города его нет.
15. **`defaults write com.tmmt.Aza` может уйти не туда.** От прежних
   sandbox-сборок остался контейнер `~/Library/Containers/com.tmmt.Aza`,
   и `defaults` пишет в него, а приложение читает
   `~/Library/Preferences/com.tmmt.Aza.plist`. Для проверок писать
   полным путём к файлу.
16. **Второй хоткей Carbon молчит, если первый вернул `noErr`.**
   Обработчики стоят в ЦЕПОЧКЕ: чужой `EventHotKeyID` обязан получить
   `eventNotHandledErr`, иначе ⌘⇧A съедает событие ⌃⇧D.
