## 1. Dynamic Island на macOS — boring.notch (~10.5k★, GPL-3.0)

https://github.com/TheBoredTeam/boring.notch

Самый популярный проект «острова» вокруг выреза MacBook: hover-раскрытие,
музыка с визуализатором, календарь, полка файлов (Shelf), замена системных HUD,
заряд батареи. Реализован на SwiftUI поверх выреза, macOS 14+, есть updater
и XPC-helper. Код копировать НЕЛЬЗЯ (GPL-3.0), но это главный референс по
поведению острова:

- подтверждает жизнеспособность схемы «NSPanel у верхней границы + hover +
  раскрытие кликом + закрытие внешним кликом» — ровно ваш раздел 3 спеки;
- их roadmap (live activities, жесты, настройка размеров под разные дисплеи)
  — готовый чеклист подводных камней, о которые они уже ударились;
- зависимость MediaRemoteAdapter — способ получать Now Playing на macOS 15.4+
  (для вас неактуально, но показывает паттерн выноса привилегированной логики
  в XPC-хелпер);
- NotchDrop — их источник идеи Shelf (https://github.com/buwenaa/NotchDrop).

Вывод для Aza: ваша спека по острову (состояния, приоритеты, закрытие внешним
кликом) уже детальнее, чем у boring.notch. Использовать как чеклист edge cases:
размеры под разные диагонали, полноэкранные приложения, Stage Manager.

## 2. Локальная диктовка

### WhisperKit / Argmax OSS SDK (MIT, ~6.3k★) — базовый вариант из вашей спеки

https://github.com/argmaxinc/argmax-oss-swift (репозиторий переименован с
argmaxinc/WhisperKit — обновите ссылки в спеке, раздел 13).

- Лицензия MIT — прямое использование разрешено.
- Интеграция через Swift Package Manager, модели грузятся из Hugging Face Hub
  (Model Gallery с размерами и бенчмарками — совпадает с вашим разделом 5.4
  про карточки моделей).
- Входит `AudioProcessor` (загрузка/нарезка аудио), streaming-транскрипция.
- Бесплатный OSS-SDK покрывает базовый путь; real-time с кастомным словарём —
  платный Pro SDK (не нужен для MVP).
- Есть BENCHMARKS.md — методика измерения скорости/точности, пригодится для
  ваших карточек моделей.

### FluidAudio (Apache-2.0, ~2.7k★) — быстрая альтернатива на Neural Engine

https://github.com/FluidInference/FluidAudio

Swift SDK полностью локального аудио-AI: Parakeet (speech-to-text), Silero-VAD,
диаризация, TTS — всё через Core ML с выгрузкой на Apple Neural Engine
(меньше памяти, быстрее инференс). Используется keyboop как движок диктовки.
Лицензия Apache-2.0 совместима с MIT-проектом (сохранить NOTICE).

Проверить перед ставкой на него: поддержка русского языка в актуальной версии
Parakeet (английская модель точно есть, мультиязычная v3 — проверить список языков).
Для Aza разумно: WhisperKit как основной путь (ру+ен гарантированно),
FluidAudio/Parakeet как «быстрый профиль» из раздела 5.4.

### Handy (MIT, ~30.2k★) — референс UX диктовки

https://github.com/cjpais/Handy · handy.computer

Кроссплатформенная диктовка «нажал хоткей — сказал — текст вставлен», офлайн.
Стек: Tauri + Rust, инференс через ggml/transcribe.cpp (whisper.cpp-семейство),
**Silero VAD** для детекции голоса.

Что взять:

- Silero VAD — лёгкая детекция активности голоса: пригодится для живой
  waveform в вашем острове и для отсечения тишины до отправки в модель.
- Паттерн лицензии: код MIT, но имя/логотип/бренд исключены из open source —
  полезный прецедент для Aza, если захотите защитить бренд.
- Их список известных багов (самопроизвольный старт записи, обрыв на ~2 мин)
  — напоминание тестировать длинные записи и циклы событий хоткея.

## 3. Буфер обмена

### Maccy (MIT, ~21.3k★) — главный референс, код совместим с Aza

https://github.com/p0deje/Maccy · maccy.app

Эталонный легковесный менеджер буфера на чистом Swift/AppKit. Конкретика,
которую стоит перенести в вашу реализацию (раздел 8 спеки):

| Механика Maccy | Для Aza |
|---|---|
| Игнорируемые типы pasteboard: `org.nspasteboard.TransientType`, `org.nspasteboard.ConcealedType`, `org.nspasteboard.AutoGeneratedType` | Ровно ваши «confidential/transient items» из раздела 8.9 — стандарт де-факто |
| Дефолтный игнор-лист приложений: 1Password (`com.agilebits.onepassword`), KeeWeb (`net.antelle.keeweb`) | Готовый стартовый список менеджеров паролей |
| `com.apple.is-remote-clipboard` | Исключение Universal Clipboard — сценария нет в вашей спеке, добавить |
| Опрос pasteboard каждые 500 мс (настраивается) | Базовая схема мониторинга; таймер дешевле, чем наблюдатели |
| Вставка требует Accessibility | Совпадает с вашим подходом прямой вставки |
| Переводы через Weblate | Вариант инфраструктуры локализации (ru/en + позже ce) |

Отдельная задача, которой нет ни у одного из опенсорс-референсов: **шифрование
истории на диске** (ваш раздел 8.9). Ни Maccy, ни PasteBar не шифруют историю —
это будет вашим отличием. Паттерн: CryptoKit AES-GCM для записей, ключ в
Keychain (kSecClassGenericPassword), SQLite/Core Data как индекс. Реализаций
«на коробке» нет — это R&D-задача Этапа 2, заложите время.

### PasteBar (~2.1k★, CC BY-NC) — только идеи, код брать нельзя

https://github.com/PasteBar/PasteBarApp

Функционально ближе всего к вашему разделу 8 (коллекции, PIN-защита коллекций,
блокировка экраном, бэкап/восстановление базы, автоопределение языка кода).
Но лицензия Creative Commons BY-NC — несовместима с MIT-кодовой базой.
Стек (Tauri/Rust/SQLite) для нативной Aza нерелевантен. Брать только UX-идеи:
PIN на избранных коллекциях — хорошая идея для вашего раздела «Избранное».

## 4. Время намаза

### Adhan / adhan-swift (MIT) — готовый расчётный движок, прямое попадание

https://github.com/batoulapps/adhan-swift · SPM, ~229★

Это ровно ваш «локальный астрономический расчёт с региональным профилем»
(приоритет 2 из раздела 4.3 спеки):

- высокоточные астрономические формулы из книги Jean Meeus «Astronomical
  Algorithms» (рекомендована US Naval Observatory);
- пресеты `CalculationMethod`: muslimWorldLeague, egyptian, karachi,
  ummAlQura, dubai, moonsightingCommittee, northAmerica, kuwait, qatar,
  singapore, turkey и др.; углы fajr/isha настраиваются вручную;
- `madhab` (shafi/hanafi) для Асра — совпадает с вашим разделом «Настройки → Намаз»;
- готовые API: `currentPrayer()`, `nextPrayer()`, `time(for:)` — прямой
  источник для вашего обратного отсчёта в острове;
- бонус-функции: SunnahTimes (последняя треть ночи), Qibla (направление от севера).

Критично важно: существует общий репозиторий **adhan-testdata** со сверенными
временами намаза для всех реализаций — готовые фикстуры для ваших тестов.

Вывод: не писать свой расчёт. Взять adhan-swift, обернуть в протокол
`PrayerScheduleProvider`, рядом сделать второй провайдер «ДУМ/мечеть» —
архитектура источников из раздела 4.3 ложится на это идеально.

### Источники расписаний и API

- **Aladhan Prayer Times API** (Islamic Network, бесплатный) —
  https://aladhan.com/prayer-times-api : эндпоинты по координатам и городам,
  все методы расчёта, таймзоны. Есть страницы городов России (включая
  Махачкалу). Подходит для сравнительного контроля качества расчёта.
- **EzanVaktiAPI** — https://github.com/furkantektas/EzanVaktiAPI (~84★):
  открытый API поверх официальных данных турецкого Diyanet. Это прецедент
  «обёртки над официальным расписанием государственного муфтията» — полезная
  модель для вашей интеграции с ДУМ РФ/ЧР, если их данные будут доступны
  машиночитаемо (юридическую сторону вы уже правильно пометили в разделе 4.3).
- **Awesome-Muslims** — https://github.com/choubari/Awesome-Muslims (~612★):
  курируемый список open-source исламских ресурсов (расписания, азаны, Коран,
  кибла). Пройтись по нему при проектировании Этапа 4 — там же аудио азана
  с открытыми лицензиями (ваша потребность из раздела 4.4).

## 6. Что добавить в план Aza по итогам исследования

### Этап 3 (диктовка)
1. Оставить WhisperKit основным движком (ру+ен гарантированы); оценить
   FluidAudio/Parakeet как «быстрый профиль» после проверки русского языка.
2. Добавить Silero VAD (через FluidAudio или отдельно) для живой waveform
   и отсечения тишины.
3. Обновить ссылку на репозиторий WhisperKit в спеке (раздел 13):
   теперь argmaxinc/argmax-oss-swift.

### Этап 4 (намаз)
4. Принять adhan-swift как расчётный провайдер; определить протокол
   `PrayerScheduleProvider` с двумя реализациями: AdhanProvider и
   MosqueScheduleProvider (ДУМ).
5. Использовать adhan-testdata как фикстуры тестов расписаний.
6. Aladhan API — источник сверки качества; Awesome-Muslims — поиск аудио азана
   с открытой лицензией.
7. Спека-идея: SunnahTimes и Qibla у adhan-swift «бесплатны» — учесть при
   планировании пост-MVP (сейчас в разделе 17 они исключены).

### Этап 2 (буфер)
8. Взять игнор-листы Maccy за основу раздела 8.9: три стандартных типа
   nspasteboard + 1Password/KeeWeb + `com.apple.is-remote-clipboard`.
9. Опрос pasteboard таймером ~500 мс с настраиваемым интервалом.
10. Шифрование истории (CryptoKit AES-GCM + ключ в Keychain) — выделить как
    R&D-задачу Этапа 2: готовых опенсорс-референсов нет, это отличение Aza.

### Остров (Этап 0–1)
11. Прочитать issues/roadmap boring.notch как чеклист edge cases NSPanel:
    разные диагонали, полноэкранные приложения, Stage Manager, внешние мониторы.
    Код GPL — не копировать.
