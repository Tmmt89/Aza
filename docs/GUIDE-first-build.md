# Гайд для новичка: первый запуск конвейера словаря

> Пошаговая инструкция «что делать руками». Предполагается, что вы никогда
> не работали с терминалом и HuggingFace. Выполнять по порядку.

## Шаг 0. Что вообще происходит

У Aza будет чеченский словарь частот: файл, где для каждого слова указано,
сколько раз оно встретилось в чеченских текстах. Он нужен приложению, чтобы
(а) понимать, что перед ним чеченское слово, (б) правильно чинить палочку,
(в) позже — исправлять опечатки.

Словарь не пишется руками: программа (`Tools/BuildChechenLexicon`) скачивает
готовые тексты на чеченском, считает слова и выдаёт один файл `lexicon.tsv`.
Сейчас нужно подготовить тексты и запустить программу.

## Шаг 3. Скачать исходные тексты

Найденные реальные источники:

| Источник | Что это | Объём | Лицензия |
|---|---|---|---|
| `lingtrain/chechen-russian` | параллельный корпус (предложение che ↔ ru), колонка `che` | 31 064 пар | не указана → уточнить |
| Чеченская Википедия (`wikimedia/wikipedia`, конфиг `ce`) | энциклопедический бытовой текст | большой | CC BY-SA 4.0 |
| `NM-development/chechen_given_names_bessmertnybarak_v0` | имена собственные (полезно списком never-touch) | ~10K | MIT |

Главный источник сейчас — lingtrain. Файлы там лежат в формате parquet,
поэтому их надо один раз превратить в обычный текст:

```bash
mkdir -p sources && cd sources

# скачать parquet-файл (адрес = resolve-URL с закреплённой ревизией)
curl -L -o chechen-russian.parquet \
  "https://huggingface.co/datasets/lingtrain/chechen-russian/resolve/296c9a27ea62dcb1ebf72b9253fd84b199101d89/data/train-00000-of-00001-9781d292a74ae792.parquet"

# установить библиотеки Python (один раз)
pip3 install pandas pyarrow

# вытащить чеченскую колонку в обычный текст
python3 - <<'PY'
import pandas as pd
df = pd.read_parquet("chechen-russian.parquet")
df["che"].to_csv("sources_che.txt", index=False, header=False)
print("строк:", len(df))
PY
```

Результат: файл на ~31 тысячу чеченских предложений. Вернуться назад:
`cd ..`

## Шаг 4. Отложить проверочный текст (до сборки!)

Чтобы честно замерить покрытие, нужен текст, который словарь НЕ видел.
Отложите каждую 50-ю строку в отдельный файл:

```bash
awk 'NR % 50 == 0' sources/sources_che.txt > sources/heldout_eval.txt
awk 'NR % 50 != 0' sources/sources_che.txt > sources/train_main.txt
```

- `train_main.txt` пойдёт В словарь;
- `heldout_eval.txt` пойдёт НА ПРОВЕРКУ покрытия.

Когда появятся другие источники (Википедия, проза) — держите проверочный
файл именно из них, а не из того же корпуса: это более честный тест.

## Шаг 5. Заполнить config.json

Скопируйте пример и отредактируйте:

```bash
cp config.example.json config.json
```

Минимальный рабочий вариант:

```json
{
  "minCount": 2,
  "sources": [
    {
      "id": "parallel",
      "url": "sources/train_main.txt",
      "revision": "local-train-main-v1",
      "columnIndex": null,
      "hasHeader": false,
      "maxShare": 1.0
    }
  ]
}
```

Локальный путь — это нормально: конвейер понимает и адреса https://…,
и локальные файлы. Когда добавите новые источники — просто дописывайте блоки
в массив `sources`. Для каждого сетевого источника фиксируйте хеш ревизии:
на странице датасета HuggingFace нажмите на номер коммита рядом с файлом —
это и есть `sha`.

## Шаг 6. Собрать словарь

```bash
swift run BuildChechenLexicon build --config config.json --out out_lexicon
```

Ожидаемый вывод: сколько слов вошло, сколько выброшено, коэффициенты источников.
Проверьте глазами первые строки результата:

```bash
head -20 out_lexicon/lexicon.tsv
```

Каждая строка: слово, частота, флаг «только с заглавной». Частые слова должны
быть узнаваемыми («ду», «иш»…). Если сверху мусор — разберём фильтры.

## Шаг 7. Точка go/no-go: замерить покрытие

```bash
swift run BuildChechenLexicon coverage \
  --lexicon out_lexicon/lexicon.tsv \
  --eval sources/heldout_eval.txt
```

Интерпретация:

- **≥ 70%** — отлично: словарь готов к исправлению опечаток, идём в приложение.
- **60–70%** — серая зона: полезен для защиты от ложной латинизации и
  нормализации палочки; опечатки пока нет. Стоит добавить источников.
- **< 60%** — ожидаемо для одного параллельного корпуса из 31k пар. Это НЕ
  провал проекта: подключайте Чеченскую Википедию и другие тексты как
  дополнительные источники в config.json и пересобирайте.

## Шаг 8. Разрешение и лицензия (блокирует публикацию, не эксперименты)

Пока словарь лежит у вас локально — ничего оформлять не нужно. Но прежде чем
коммитить `lexicon.tsv` в публичный репозиторий или класть его в DMG:

1. Выясните лицензию каждого источника (карточка датасета на HuggingFace).
2. Если лицензия не указана — написать автору (у lingtrain есть контакты в карточке).
3. Записать выводы в `docs/PLAN-chechen.md`, раздел про лицензию артефакта.

## Если что-то пошло не так

- `command not found: swift` → установите Xcode Command Line Tools:
  `xcode-select --install`.
- `HTTP 404` при загрузке → опечатка в URL или хеше ревизии.
- `локальный файл не найден` → путь в config.json относительный, а терминал
  открыт не в той папке; вернитесь к шагу 1.
- Странные символы вместо чеченских букв → файл сохранён не в UTF-8; экспорт
  из parquet всегда даёт UTF-8, значит перепутан файл.
