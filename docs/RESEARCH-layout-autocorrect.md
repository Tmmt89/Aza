# Исследование: готовые blueprint'ы автозамены раскладки и автокоррекции

> Результаты обзора open-source проектов и библиотек по состоянию на 24.08.2026.
> Цель: найти проверенные подходы для модуля «Раскладка» (раздел 6 спецификации Aza)
> и чеченской автокоррекции (раздел 7), не изобретая велосипед.

## Вывод кратко

Да, blueprint'ы существуют, и несколько проектов решают ровно вашу задачу
(`ghbdtn → привет` на macOS). Два из них под лицензией MIT — их архитектуру можно
изучать детально и даже переиспользовать идеи/код с атрибуцией. Проекты под
GPL-3.0 — только читать для понимания подходов, код копировать НЕЛЬЗЯ (Aza — MIT).

## 1. RuSwitcher (MIT, ~176★) — главный технический референс

https://github.com/rashn/RuSwitcher · macOS 13+, чистый Swift + AppKit.

Исправляет неверную раскладку тапом Option или автоматически, без буфера обмена.
В README открыто перечислен техстек — он почти дословно совпадает с вашим
прототипом и подтверждает его правильность:

| Приём RuSwitcher | Что это даёт Aza |
|---|---|
| `CGEventTap` (пассивный, listen-only) | Альтернатива вашему `NSEvent.addGlobalMonitorForEvents`; надёжнее для системного мониторинга |
| **`UCKeyTranslate` (Carbon)** | Динамический маппинг символов между ЛЮБОЙ парой установленных раскладок — без захардкоженных таблиц QWERTY↔ЙЦУКЕН |
| `CGEvent.keyboardSetUnicodeString` | Прямая печать исправленного текста без буфера (работает даже в Electron/VS Code) |
| Маркер `CGEventSource.userData` | Фильтрация собственных синтетических событий — вы уже делаете точно так же (.eventSourceUserData), подход подтверждён |
| `AXUIElement` | Определение сфокусированного элемента — как у вас |
| Память раскладки по приложению | Запоминает активную раскладку каждой программы, восстанавливает при возврате |
| Три списка исключений | apps / never-convert / always-convert — готовая модель для раздела 6.3 вашей спецификации |
| Режим Screen Sharing | Отдельная обработка удалённого стола — сценария нет в вашей спеке, стоит добавить |

Лицензия MIT — код можно изучать построчно и переносить с сохранением копирайта.

## 2. keyboop (MIT, ~184★) — ближайший продуктовый аналог Aza

https://github.com/iffuno/keyboop · keyboop.com

Та же комбинация, что и у вас: исправление раскладки + локальная диктовка +
приватность («ни байта в сеть»). Чему учит:

- **Диктовка через whisper.cpp + Parakeet (FluidAudio) на Neural Engine** —
  альтернатива WhisperKit, работает на M1+. Учитывать при выборе стека Этапа 3.
- **Гибкое окно отката**: не только последнее слово, но N слов / фраза /
  всё за последние T секунд одним хоткеем. Хороший UX-паттерн для вашей
  кнопки ⌘Z после автокоррекции.
- **Сниппеты**: набрал сокращение — получил фразу. Идея для бэклога.
- **Gotcha сборки whisper.cpp**: без `CMAKE_OSX_DEPLOYMENT_TARGET=14.0`
  ggml-metal линкуется с классом из macOS 15, приложение молча падает до
  `main()`. Записать в будущий build-док.
- Зависимости в `vendor/`, Developer ID + нотаризация, Sparkle для обновлений —
  тот же путь распространения, что раздел 14 вашей спецификации.

## 3. LayoutFix (MIT, маленький проект) — blueprint архитектуры

https://github.com/Drotfix/LayoutFix

Молодой проект, буквально ваш кейс (`ghbdtn → привет` по хоткею). Самое ценное —
структура репозитория:

```
Sources/LayoutFixCore/     // ЧИСТАЯ логика без AppKit: раскладки, детекция, конвертация
Sources/LayoutFix/         // Приложение: менюбар, хоткеи, Accessibility, настройки
Tests/LayoutFixCoreTests/  // Юнит-тесты ядра + Fixtures/real_world_examples.json
docs/architecture.md       // Описание архитектуры
docs/adding-a-language.md  // Гайд: как добавить язык
```

Это ровно то разделение, которое предложено в HANDOVER.md (блок C):
чистое ядро коррекции отдельно от системного слоя, покрытое тестами на
фикстурах реальных примеров. Берите за образец.

Детектор направления конвертации: **частотные словари + биграммы**, конвертация
только при достаточной уверенности — совпадает с вашим требованием «если
уверенность недостаточна, слово не меняется».

Практический лайфхак (важен для дев-процесса): разрешение Accessibility привязано
к подписи. При ad-hoc подписи отпечаток меняется каждую сборку, и галочка в
системных настройках слетает. Решение — стабильный самоподписанный сертификат
codesign (у вас уже есть identity "Aza Development" — эта проблема у вас решена).

В их роадмапе: генерация таблиц раскладок из системы через `UCKeyTranslate`
вместо ручных — ещё одно подтверждение приёма из RuSwitcher.

## 4. SymSpell (MIT!) — движок чеченской автокоррекции

https://github.com/wolfgarbe/SymSpell · Лицензия: MIT (проверено по файлу
LICENSE, (c) 2018 Wolf Garbe) — можно использовать в Aza напрямую.

Классический алгоритм symmetric delete для проверки орфографии:

- поиск кандидатов по расстоянию Дамерау-Левенштейна до ~2 правок;
- на порядки быстрее наивного перебора: генерируются только удаления
  (transposes/replaces/inserts превращаются в deletes терминов словаря);
- префиксная индексация → экономия памяти >90%;
- языкозависим: нужен частотный словарь языка.

Как применить в Aza:

1. Портировать на Swift (~500 строк; порты на другие языки существуют).
2. Собрать частотный словарь чеченского корпуса — готового hunspell-словаря
   чеченского в LibreOffice/dictionaries НЕТ (проверено: папки `ce` там нет),
   т.е. корпус придётся собирать самостоятельно. «Подтверждённые слова» из
   раздела 7.4 вашей спеки отлично встраиваются — они просто повышают частоту
   записи в локальном словаре.
3. Предобработка перед SymSpell: нормализация `1/I/l → Ӏ` — тогда все варианты
   попадают в одну каноническую форму и словарь нужен в единственном написании.
4. Порог уверенности: принимать кандидата только при edit distance ≤ 1–2 и
   заметно большей частоте, чем у альтернатив — соответствует вашему принципу
   «исправлять только очевидные ошибки».

Альтернатива поменьше: алгоритм Норвига ("How to Write a Spelling Corrector") —
проще, но медленнее на больших словарях. Для MVP с маленьким чеченским словарём
хватит даже BK-tree; SymSpell — выбор с запасом на рост.

## 5. Проекты автопереключения источника ввода (GPL-3.0 — только читать)

- **Input Source Pro** — https://github.com/runjuu/InputSourcePro (~3.5k★).
  Переключение источника ввода по приложению И ПО САЙТУ в браузере, индикатор
  раскладки, force-английская пунктуация для IDE/терминала.
- **SwitchKey** — https://github.com/itsuhane/SwitchKey (~960★). Запоминание
  выбранного источника ввода на приложение.
- **LockIME** — https://github.com/oomol-lab/LockIME (~550★). Блокировка
  источника ввода глобально / по приложению / по URL.

Из них брать ТОЛЬКО идеи (per-app/per-URL правила, индикатор, пунктуация),
не код — лицензия GPL-3.0 несовместима с MIT-кодовой базой Aza.

Мелкие MIT/Swift проекты той же ниши для сверки подходов:
perekluk (тап Option = фикс слова), relayout (⌘Fn, layout-agnostic),
langSwitcher (двойной Shift, greedy-детекция строки), bzz (авто-режим).

## 7. Что конкретно добавить в план Aza (обновление блоков C и D из HANDOVER.md)

1. Вместо ручной таблицы QWERTY↔ЙЦУКЕН — динамический маппинг через
   `UCKeyTranslate` (подход RuSwitcher). Автоматически поддержит украинскую
   и другие раскладки позже.
2. Рассмотреть `CGEventTap` вместо `NSEvent.addGlobalMonitorForEvents`
   в WordMonitor (тот же пассивный listen-only режим, но надёжнее).
3. Тесты ядра на JSON-фикстурах реальных примеров (паттерн LayoutFix):
   `ghbdtn→привет`, смешанные строки, `1алам→Ӏалам`, исключения.
4. SymSpell (MIT) как основа LayoutCorrectionEngine для чеченского; сборка
   корпуса словаря — отдельная задача; в спецификацию раздела 7 добавить пункт
   «источники корпуса и их лицензии» — сейчас это белый лист.
5. Спека-идея: окно отката N последних слов (keyboop) вместо отмены только
   последнего исправления.
6. Спека-идея: режим Screen Sharing / удалённого стола (RuSwitcher) — известный
   источник ложных срабатываний автокоррекции.

## 8. Статус внедрения

- **Пункт 1 (`UCKeyTranslate`) — внедрён 25.08.2026**, `Aza/Core/KeyboardLayoutMap.swift`.
  Рекомендация подтвердилась эмпирически: захардкоженная таблица QWERTY↔ЙЦУКЕН
  была неверна для системной раскладки macOS «Russian». Проверка через
  `UCKeyTranslate` показала, что `ё` находится на клавише `\` (а `` ` `` даёт `]`),
  тогда как таблица предполагала Windows-раскладку с `ё` на `` ` ``. Теперь карта
  строится из установленных раскладок, кэшируется и умеет любую пару языков.
- Пункты 2–6 не внедрены.
