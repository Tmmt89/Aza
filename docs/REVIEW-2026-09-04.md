# Ревью Aza — 4–5 сентября 2026

Проверено текущее рабочее дерево целиком: код приложения, тесты, конвейер словаря, Python- и shell-инструменты, настройки сборки. Основания: `docs/SPEC.md`, `HANDOVER.md` и планы реализации. До начала работы в проекте уже были незакоммиченные изменения; они сохранены. Ниже перечислены исправления этого ревью, а не весь diff относительно HEAD.

Окончательный прогон: **66 тестов приложения + 16 тестов конвейера словаря, без ошибок**. Добавлено 13 тестов приложения, расширены существующие. Также прошли `python3 Tools/test_tools.py`, `py_compile` для Python-скриптов, `bash -n` отдельно для каждого shell-скрипта, обязательная проверка таблиц палочки и `git diff --check`. `codesign --verify --deep --strict` подтвердил подпись Aza Development.

Приложение проверено командой `xcodebuild -project Aza.xcodeproj -scheme Aza -configuration Debug -destination 'platform=macOS,arch=arm64' CC=/tmp/aza-review-clang test`. ## Границы проверки

- Это аудит исходников с регрессиями, а не доказательство отсутствия всех возможных ошибок.
- Живые сценарии микрофона, Focus, сна/пробуждения, блокировки и Accessibility в сторонних редакторах требуют проверки запущенного подписанного приложения. В рамках ревью пользовательские данные не очищались и рабочее приложение не перезапускалось.
- Пауза снимает будущие уведомления. Системный звук, уже доставленный до начала паузы, этот API остановить не позволяет. Независимый повторный просмотр переходов pause/resume новых P1/P2 гонок не выявил.
- Эвристика технических токенов не является полным RFC-парсером: quoted local-part email со встроенными пробелами остаётся ограничением. AX-слепые поля позволяют проверить только доступную системе информацию о фокусе.
- Локальный Xcode зависал до компиляции, на verbose-опросе clang. Временная обёртка вне репозитория удаляет только длинную строку диагностической команды cc1 при опросе /dev/null; исходники компилирует тот же clang. Подпись Aza Development сохранена.

## Дополнение: исчезновение острова при диктовке

По сообщению пользователя 5 сентября проверен сценарий, когда остров диктовки появлялся только после открытия и закрытия меню мышью. Вставка текста вызывает `NSApp.hide()`: обычная NSPanel при этом исчезает, хотя `IslandStore.isIslandVisible` остаётся true. Переход между компактным режимом и диктовкой не меняет размер, а повторное true отсекается `removeDuplicates`, поэтому окно могло остаться скрытым.

В `IslandPanelController.makePanel` выставлено `canHide = false`: остров остаётся под управлением собственного контроллера видимости, а системное скрытие настроек больше его не прячет. В отдельном AppKit-процессе воспроизведено скрытие обычной панели и проверено, что исправленная панель его переживает, допускает явный `orderOut` и повторный показ без перехвата фокуса. [Лог проверки](/tmp/aza-window-hide-probe.log). После изменения повторно прошли все 66 тестов приложения.

## Дополнение 05.09.2026: отказ от Keychain

По прямому запросу владельца ключ истории теперь хранится в
`Application Support/Aza/clipboard-history.key` (256 бит, права 0600,
каталог 0700). Debug и Release используют один путь. Все обращения
приложения к Keychain, включая чтение, создание и удаление при очистке,
удалены. Подпись сборки остаётся «Aza Development».

При первом запуске подходящий `debug-history.key` переносится в новый файл,
исходные байты сохраняются. История и её копия не перешифровываются при
переносе. Изображения, которые могут относиться к резервной копии,
не удаляются уборкой сирот. Без доступного локального ключа существующая
история остаётся на диске, запись блокируется. Старые элементы Keychain
не читаются и не удаляются. Шифрование AES-GCM сохранено, но другие процессы
той же учётной записи имеют доступ к файловому ключу.

Проверки: 69 XCTest-тестов прошли, включая создание и повторное чтение
ключа, права доступа, перенос обычного и повреждённого старого ключа,
сохранность истории/резервной копии/изображений, отказ на символических
ссылках, FIFO и ошибках чтения. CLI-регрессии и синтаксис скриптов прошли.
Отдельная проверка без изменения пользовательских файлов подтвердила:
существующий локальный ключ открывает текущую историю владельца.

Обновлён `dist/Aza-1.0.dmg` (arm64, около 5 МБ). Проверены контрольная
сумма образа, подпись DMG и приложения, точное совпадение содержимого
смонтированного образа со сборкой Release. В импортируемых символах
релизного бинарника нет API `SecItem`/`SecKeychain`. Приложение владельца
не перезапускалось, новая сборка автоматически не устанавливалась.
