# План: чеченский лексикон — от корпуса до автокоррекции

> План принят по итогам обсуждения. Реализация конвейера: `Tools/BuildChechenLexicon/`
> (готова, покрыта тестами). Этот документ — источник истины по стратегии.
>
> **РЕШЕНИЕ (25.08.2026): каноническая палочка проекта — строчная U+04CF («ӏ»).**
> Заглавная U+04C0 («Ӏ») распознаётся везде как та же буква, но нигде не
> порождается: ни в конвейере, ни в движке коррекции, ни в примерах
> документации. Проверка: `python3 Tools/palochka_audit.py .`


## 1. Конвейер сборки (реализован)

Офлайн-инструмент вне приложения. Загрузка датасетов с HuggingFace с
закреплением ревизии по хешу; только чеченская сторона корпусов; токенизация,
где `1` внутри кириллического слова не граница; канонизация САМОГО корпуса
(подмены `1/I/l` и обе кодовые точки палочки U+04C0/U+04CF → единая форма);
нижний регистр + флаг «только с заглавной» (отделяет имена собственные);
отсев слов ниже порога вхождений и всего не-кириллического; взвешивание
источников с потолком доли каждого (`maxShare`), чтобы религиозные тексты
не задавили бытовую лексику.

Выход: `lexicon.tsv` (слово \t частота \t capitalOnly) + `manifest.json`
(версия, дата, хеши ревизий, параметры) — воспроизводимая сборка.

## 2. Точка go/no-go

До написания кода в приложении замерить покрытие словарём ОТЛОЖЕННОЙ части
корпуса (новости/проза, НЕ Писания): `swift run BuildChechenLexicon coverage …`.

- **≥ 70%** → идём дальше: словарь пригоден для исправления опечаток.
- **< 70%** → стоп для опечаток; словарь всё равно полезен как защита от
  ложной латинизации и для точной нормализации палочки.

Ожидаемый риск: 57% корпуса — словарь начальных форм, а чеченский богат
словоизменением. Частично лечится корпусом и пользовательскими подтверждёнными
словами, полностью — только морфологическим анализатором (вне MVP).

## 3. Три применения в приложении (по возрастанию риска)

1. **«Это чеченское слово?»** — слово чеченское, если есть в словаре ИЛИ
   содержит один из маркеров орфографии (ӏ, хь, къ, кх, аь, оь, уь, юь, яь).
   Маркеры остаются подстраховкой для форм вне словаря. Безопасно: только
   ЗАПРЕЩАЕТ менять текст.
2. **Точная нормализация палочки** — проверка гипотез: перебор вариантов
   подмен (`Normalizer.hypotheses`, обычно 2–4), принимается вариант, который
   есть в словаре; 0 или >1 совпадений → не трогаем. Улики: смесь кириллицы
   с латинской I/l — почти наверняка палочка (сильнее цифры); `1` в конце
   слова — скорее нумерация, трактовать осторожно.
3. **Исправление опечаток** — отдельная настройка, выключена по умолчанию.
   Жёсткие условия принятия: слова нет в чеченском словаре; оно НЕ допустимое
   русское слово (смешанный ввод — норма); кандидат ровно один на расстоянии
   одной правки; длина ≥ 4; нет в пользовательских исключениях. Ложное
   исправление хуже пропуска.

## 4. Почему без SymSpell (пока)

Рабочее расстояние правки — единица (ради безопасности). На единице индекс
удалений SymSpell не нужен: генерируем все варианты в одну правку набранного
слова (~600 проверок для 7 букв) и сверяем с хеш-множеством — доли миллисекунды.
~30 строк вместо ~500, без чужого кода и индекса в памяти. SymSpell вернуть,
если понадобится расстояние 2 на сотнях тысяч слов.

## 5. Хранение

- Ленивая загрузка при первом чеченском слове (не при запуске).
- Формат для старта: TSV в множество; ~100 тыс. слов ≈ 10 МБ RAM, <100 мс загрузка.
- Если много: сортированный бинарный файл + mmap + двоичный поиск. Сначала измерить.
- Файл — в ресурсах приложения рядом с лицензией. Если лицензия корпуса не
  разрешает распространение в DMG — скачивание при первом включении функции;
  это единственная новая сетевая операция, её надо добавить в раздел
  приватности спецификации.

## 6. Пользовательский слой

- Два независимых переключателя: «нормализация 1 → ӏ» и «орфографическая
  автокоррекция» (вторая не требует первой и наоборот).
- Отмена: ⌘Z где поддерживается + двойное нажатие правого Shift глобально;
  после отмены — предложение занести слово в исключения.
- Два пользовательских списка (JSON в Application Support, отдельно от базы
  буфера): никогда-не-трогать и подтверждённые слова (добавляются к словарю,
  постепенно чинят проблему покрытия). При «удалить все данные» чистятся оба.

## 7. Проверка носителем — измеримо

Прогнать движок по отложенному корпусу, выгрузить ВСЕ предлагаемые исправления
таблицей «было → стало»; salgiri отмечает каждое верное/неверное; считаем точность.

- Порог автоприменения ≈ **98%**: цена ошибки асимметрична — пропущенная
  опечатка мелочь, подменённое слово в чужом сообщении — стыдно.
- Ниже порога → функция остаётся выключенной, исправления показываются подсказками.
- Разметка становится тестовыми фикстурами (JSON реальных примеров).

## 8. Риски

| Риск | Митигация |
|---|---|
| Религиозный перекос корпуса (~39% Писания) | Взвешивание источников с maxShare |
| Начальные формы вместо словоформ | Корпус + подтверждённые слова; полностью не решается без морфологии |
| Отзыв разрешения датасета | Словарь — отдельный лицензированный артефакт, не в MIT-исходниках |
| Русско-чеченский смешанный ввод | Каждая проверка сначала спрашивает «а не русское ли это слово» |
| Диалекты / близость к ингушскому | Незнакомая форма не исправляется, только помечается неизвестной |

## 9. Порядок работ

1. **Текст разрешения на корпус** — блокирует всё остальное.
2. Конвейер (✅ готов в `Tools/BuildChechenLexicon`) + замер покрытия = go/no-go.
3. Словарь как защита от ложных исправлений + точная нормализация палочки
   (основная польза почти без риска).
4. Круг проверки носителем.
5. Только после него — орфографическая автокоррекция, выключенная по умолчанию.
